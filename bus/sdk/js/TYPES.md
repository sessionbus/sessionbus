# Wire types

DTO declarations are generated by [Tygo](https://github.com/gzuidhof/tygo) from
`sdk/go/protocol/types.go` and shipped in this package. Use a type-only import:

```ts
import type { SessionListResult, SessionSelfInfo } from '@sessionbus/kit/protocol';
```

`protocol` is a **type-only module**; it exports no JavaScript values or constants.
JavaScript consumers can use JSDoc `import('@sessionbus/kit/protocol')` types.
`Caller` methods reference these declarations for request and response shapes,
including `list()` returning `Promise<SessionListResult>`. Existing JavaScript
methods retain their existing signatures. This is not a declaration of the
entire SDK runtime API; projects checking JavaScript SDK implementation files can
use TypeScript's `allowJs` and `maxNodeModuleJsDepth` (the package fixture checks
`Caller` at depth 1).

The declarations describe protocol DTO shapes, not every valid or invalid JSON
value. `session.schema.json` remains the shared Go/JavaScript runtime validation
contract: it enforces required combinations, allowed strings, safe integer
ranges, frame limits and other rules that Go structs alone do not describe.

- JSON field names and `omitempty` come from Go tags. Optional pointers are
  represented as omitted properties, not `null`; current protocol validation
  rejects null for these fields.
- `WorkerHello` embeds `HelloDescription` with a Tygo `extends` source hint to
  match Go's flattened JSON encoding. Defined types and aliases retain references
  to their underlying DTOs (`SessionSelfInfo` uses `DeliverySource`).
- `json.RawMessage` and `any` become `unknown`, so consumers must narrow arbitrary
  JSON before using it. Raw messages are parsed JSON values, not byte arrays.
- Go integer fields become JavaScript `number`, including `int64`; validators
  enforce protocol-safe integer bounds. They are not `bigint`.
- Required slices and maps describe validated non-null arrays/objects. These
  declarations do not describe invalid nil-backed Go values before validation.

`self_info` is optional when reading responses from older daemons. Current
servers supply the originating caller even when filters exclude its session row.
The identity comes from the bound connection; never infer it from list order or
name matching.

To regenerate and check from a source checkout:

```sh
npm run generate:types --prefix bus
npm run check:types --prefix bus
npm run test:types --prefix bus
```

Generation uses a pinned build-only Go tool module; package consumers do not need
Go, Tygo or a new runtime dependency. The test command downloads a pinned
TypeScript compiler for an isolated, temporary installed-package type check.

## JavaScript stream write ownership

`Connection` retains submitted writes until their callback or the stream's actual
`close` event. Actual close rejects writes whose callbacks were omitted; it never
reports a successful write. Calling `destroy()` or logically closing the connection
is not proof that the stream has closed. A supplied stream must complete callbacks
or emit `close` for outstanding writes to settle. Late callbacks after settlement,
including errors after a successful callback, have no effect.
`Connection.done` marks logical connection closure and can resolve before write
settlement; consumers joining transport work must also await actual stream close
and their owned operations.

The existing 1 MiB encoded frame limit is unchanged. Independently of the 256
pending RPC correlations, a connection allows at most 256 outstanding writes and
32 MiB of their encoded bytes, including result/error responses. Admission beyond
either write limit rejects with `busy` before writing and leaves earlier writes
and the connection intact. Callback, synchronous write failure, or actual close
releases each reservation once. These limits bound owned encoded payload, not
JavaScript object overhead or process RSS; there is no preallocated buffer pool.
For result/error replies, the owning peer or worker can still retire the connection
under its existing failed-reply-write policy when admission rejects with `busy`.

Transfer-capable connections additionally have four bulk correlations and four
encoded bulk writes, including the one actually being written, bounded at 88 KiB
each. Bulk does not consume the 256 ordinary slots. Request IDs are allocated at
writer selection; eight control frames yield to one eligible bulk frame, with
round-robin selection across transfer IDs. The one physical NDJSON frame already
being written cannot be preempted. A stalled stream gives no finite latency bound.

## Endpoint-local transfers

`connectPeer` and `Worker` use the SDK's direct filesystem executor by default,
as the current OS user in every product/mode. No native policy/mode mapping or
permission-scope refusal is applied; real OS I/O failures remain failures. A raw
`Connection` owner uses `new Transfers()`, registers `handleConnectionRequest`
before `helloObserved`, supplies an identity-lifetime signal and joins
`closeConnectionGeneration` on disposal. Custom `transferExecutor` options remain
available for controlled integrations, without changing the default.

The direct implementation reads a regular file and writes one random exclusive
0600 sibling temp. No-replace publication uses atomic hard-link creation;
explicit overwrite uses atomic rename, replacing the named directory entry.
Normal OS symlinks are followed when opening the source/parent; there is no
product sandbox. The parent is resolved once. Public Node fs lacks relative
link/rename through a directory FD, so later parent replacement can make
publication/owned-temp cleanup fail; this remains an explicit charged cleanup
failure, never a claimed rollback or permission guarantee. No fsync/durability
or immutable source snapshot is promised. File identity, size and modification
time are checked on the same source handle after streaming.

Source handles provide `size()`, `read(buffer, signal)` returning a byte count,
`verify()` on the same handle, and `close()`. Destination handles provide
`write(buffer, signal)` returning a byte count, `commit()` returning
`{published: boolean, error?: Error}`, and `abort()`. Return
`{published: false, error: ErrTransferCommitUnknown}` when publication's
answer is lost. An exception or malformed commit result is conservatively
UNKNOWN. Confirmed publication remains completed even if cleanup fails. Abort
must never retract a published destination. File/temp/checked-parent FDs in
custom children count within the aggregate four per transfer; child processes,
pipes and JSON buffers need separately bounded adapter costs.

`Caller.action` accepts `transfer.offer`, `transfer.request`, `transfer.accept`,
`transfer.cancel` and `transfer.status`. Local source/destination/overwrite fields
are intercepted by `Transfers`; paths never go to the generic RPC callback.
For a raw caller, pass `{transfers}` to the `Caller` constructor. Offer/request
only bind local paths: no handle is opened before acceptance. The generation
owns submitted/accepted work independently of tool cancellation. Lost replies
are never replay authority. Ordinary message/Run delivery supplies notices;
`projectDelivery` captures the receiver-only destination on the reader and
returns a function to invoke off-reader before normal delivery. It may wait for
an already-in-flight publication fact, and never invokes filesystem work or wake.

Pending bindings are limited to eight and preparing/accepted bindings to two
across overlapping generations in one manager. Old cleanup remains charged
while normal peer reconnection continues. UNKNOWN cleanup retains its charge
until generation end; custom executors must honour cancellation and bound their
own resources. Generated wire DTOs contain no local filesystem path fields.
