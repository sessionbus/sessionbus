# Sessionbus v0.5.13

The native CLI can now stop a local managed lane without a live model session
or its former owner:

```sh
sessionbus lane archive native-session-id@host
sessionbus lane archive --socket /path/to/presence.sock native-session-id@host
```

This same-user operator command accepts an exact local ID, including an
ownerless persistent lane. It retains native history and the saved resume
recipe. Success reports an offline snapshot after the targeted wrapper has
stopped; archiving an already-offline lane succeeds without changing it. Native
close may append legitimate history. Ordinary nonpersistent-child cleanup
follows, persistent children remain, and success is not a recursive child-tree
join. Another caller can explicitly resume the ID after settlement.

The default client wait is 15 seconds. A timeout or lost reply leaves the
outcome unknown while an admitted close may continue; the command does not
retry. Archive does not restore old Run results or automatically resume work.
Ordinary public group visibility, roster behavior and close policy are
unchanged; archive uses the local same-user operator socket.

Daemon startup now validates its public/operator endpoints without requiring
space for a product lane socket, and preserves product-owned lane sockets.
The Go SDK adds `socketpath.PrepareSockets`; the existing `Prepare` behavior
remains available. These changes and the archive command are already in merged
main. The JavaScript SDK runtime and hub source are unchanged from v0.5.12.

Linux host and hub installers now verify account lingering and enable it when
needed, or stop before installation if it cannot be enabled or verified.
Lingering applies to **all user services of the account** and remains enabled
on uninstall. macOS continues to use per-user login agents, not a boot-time
system service.

This coordinated release publishes npm `@sessionbus/kit@0.5.13`, eight host/hub
archives for Linux/macOS on amd64/arm64 with `SOURCE.txt` and `SHA256SUMS`, and
the same-commit Go SDK tag `bus/sdk/go/v0.5.13`. Binary and npm publication run
separately. Updating a compiled Go consumer to the new SDK requires a dependency
update and rebuild. Publishing does not install or restart any host.

File transfer and the separate pending federation fixes are outside this
release. See the [v0.5.12 downgrade note](v0.5.12.md#downgrade) before returning
to older releases that reject duplicate lane names.
