# Sessionbus v0.5.15

This release fixes the JavaScript kit Peer shutdown witness for file transfers. A Peer previously resolved its public `closed` promise while SDK-owned transfer cleanup could still be running. Now that promise waits for every transfer generation to retire, matching the JavaScript Worker and Go Peer behavior. `shutdown()` still requests cancellation and disconnects immediately; a product awaits `peer.closed` at final disposal.

The same shared finish step covers explicit shutdown, a rejected hello and supersession. An executor close or abort failure stays in the SDK's existing local cleanup detail; it does not cause an unhandled rejection or release `closed` before retirement. A custom executor that does not complete its cancellation/close work can delay disposal, as with Worker and Go Peer. Ordinary reconnect remains independent of old-generation cleanup, whose existing capacity charges remain until retirement. No API, wire/schema, Go SDK implementation, permission, path, message text, retry or transfer publication behavior changes.

The hub now treats owner-end notification to an unattached destination as an idempotent success. Previously, ending a session that had attempted a spawn or trace change against a valid but unlinked host could close its daemon's hub link. The resulting host-end notifications could also end non-persistent remote lanes belonging to other, still-live sessions on that origin host. This consequence was established from source and a bounded controlled test, not a new live-host observation. The hub fix protects existing daemons; upgrading only a daemon while keeping an old hub retains the bug. Real owner-end errors still fail-close the origin link, including refusal at the hub's 256-call origin limit. Persistent lanes retain their existing persistence policy.

The SDK still reads and writes files directly as the OS user, without a native sandbox or approval per path. [The v0.5.14 file-transfer limits and experimental federation-policy limits](v0.5.14.md) remain unchanged, including lost final notices, uncertain publication and no automatic replay.
