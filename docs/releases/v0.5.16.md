# Sessionbus v0.5.16

This release distinguishes an unknown transfer from a failed transfer operation. In both SDKs, accepting an ID with no local binding returns `unknown_transfer`. A retained ended binding uses the same word after the existing path and role checks. Existing path, field, role and overwrite checks keep their current precedence and `transfer_binding_conflict` refusals.

An upgraded kit connected to an upgraded daemon receives `unknown_transfer` from `transfer.status` when no accessible live transfer exists, including an ended or foreign transfer. This is a refusal to provide live status, not a statement that file publication failed. The terminal notice remains the source of the outcome. It provides no terminal history or permission to retry a transfer.

The new wire refusal is explicitly negotiated per local connection. Old kits retain `transfer_failed` from new daemons; upgraded kits still work with old daemons and receive the old refusal. Interactive peers advertise an optional info key. Workers advertise only when the daemon-issued token carries the supported suffix, preserving the existing transfer, availability and policy prefix checks. The hello result is unchanged. New kits decode both refusal formats. Against an older daemon, the new optional info key appears in that peer's public info as ordinary metadata. Products receive the new status answer only after adopting kit 0.5.16 and connecting to an upgraded local daemon.

Federation and hub error formats are unchanged. A new local daemon translates only a forwarded status refusal for an opted-in local connection. Link loss and unavailable operations keep their existing errors; Accept, Cancel and other wire methods are unchanged. A later status call after a bridge retires can instead reach the local no-live-record lookup. This change adds no outcome retention, replay, queue or reconnect mechanism.

The SDK continues to read and write files directly as the OS user, without a native sandbox or approval per path. The [v0.5.15 cleanup and hub owner-end fixes](v0.5.15.md) and the [v0.5.14 transfer limits](v0.5.14.md) carry forward. Keeping an old hub retains the owner-end bug described in v0.5.15. Lost notices, uncertain publication and product-specific native limitations remain separate.

## Evidence

The retained local and forwarded ended-status tests distinguish the two emission paths. Removing only the forwarded mapping makes the forwarded-ended case fail with the legacy refusal; removing only the local mapping makes the local-ended case fail while the forwarded-ended case still passes. Selected tests on the released old implementation also reject the missing local distinction and negotiation. The in-flight bridge-loss test covers generation cancellation at the unit boundary, not a physical TLS-drop observation.

Twenty-one isolated compatibility cases use actual released kits and daemons: v0.5.15/new in both directions, v0.5.15/v0.5.15 and new/new across Go raw hello, JavaScript Peer/raw hello and both SDK workers, plus one v0.5.14 JavaScript Peer/new case. Only new/new receives the new refusal. Each interactive case observes the exact code/message pair and a later list on the same connection. Workers return the expected unavailable reason, then complete a continuity Run on the same lane after acknowledgement. Worker numeric codes and individual child-process exits are not separately observed. Preserved availability/policy flags are established by source review; the old-worker/new-daemon cases observe the transfer flag remaining usable. Other v0.5.14 equivalence is source-only.

The actual old Go and JavaScript decoders accept the legacy pair and reject the new pair; the new decoders accept both. Both reject forbidden data and mismatched code/message pairs. These compatibility observations ran at signed runtime source `8c9a3e621e860c374f7ea22cb81ed613166f0409`; the later test-expectation corrections leave all production and SDK bytes identical. The original carrier setup failure and corrected continuation are retained, with no repetition of completed cells.

These are private daemon/SDK checks, not native product or model acceptance. Product installation, per-product U-series and broader matrix evidence remain separate. The release metadata changes only `bus/package.json` and these notes; prior release notes remain unchanged.
