# Sessionbus v0.5.12

Both Go and JavaScript worker kits now allow a later explicit interrupt request
for the same outstanding Run after a product interrupt callback fails. The
failed attempt keeps its quoted worker-stderr diagnostic and answers its
initiating request with the existing Internal error (`-32603`) and string data
`product interrupt failed`, instead of an empty success result. It clears only
the captured Run's interrupt mark; there is no automatic retry.

Requests coalesced while an attempt is in flight still answer `{}`. After a
successful callback, later requests remain deduplicated. An ended Run answers
`not_running`; native-handoff intent and close handling are unchanged. An empty
interrupt result does not certify native acceptance or completion; the native
Run terminal remains the stopping outcome.

Daemon and hub source are unchanged from v0.5.11. Both SDK worker implementations
have changed. This coordinated version publishes npm `@sessionbus/kit@0.5.12`,
eight host/hub archives for Linux/macOS on amd64/arm64 plus `SOURCE.txt` and
`SHA256SUMS`, and the same-commit Go SDK tag `bus/sdk/go/v0.5.12`. The npm and
archive publication workflows run separately. Archives rebuild at the new source
revision; no product package or host installation is included.

Compiled Go consumers need a dependency update and rebuild to use the fix.
Publishing the SDK alone does not demonstrate another native interrupt in a
product integration. Failure-path evidence is from kit unit tests, not a live
native failure.

## Downgrade

Once duplicate lane names are stored, v0.5.10 refuses startup with
`invalid durable session table`. Before downgrading to it, use a daemon that
supports duplicate names to `forget` surplus lane records by exact ID, leaving
at most one per name. This deletes their Sessionbus resume records without
deleting native history.
