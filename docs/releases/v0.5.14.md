# Sessionbus v0.5.14

This release adds file transfer between sessions, bounds federated waits on a
silent host, adds an experimental optional hub federation policy, and validates outgoing
federation errors before sending them to strict clients.

## File transfer

A session can offer a file to another session, or request one, and the other
side accepts with a source or destination it chooses. The Go and JavaScript
SDKs read and write files as the OS user. The receiver writes one temporary
file, checks its streamed SHA-256 and publishes it atomically. Replacing an
existing destination requires `overwrite: true`. A transfer is at most 1 GiB.
Between hosts, bytes travel daemon → hub → daemon through separate bounded
queues. An accepted transfer holds its lanes open until it ends; a pending
offer alone does not.

Offers, requests and terminal notices arrive as ordinary messages. A transfer
ends `completed`, `failed`, `cancelled`, `expired` or `unknown`. `unknown` means
publication may have happened; it does not authorize replay or destructive
cleanup. A temporary file that could not be removed is reported to its receiver
by base name only. Transfer status or an acknowledgment is not publication
proof. Checksum verification does not promise an immutable source snapshot or
crash durability.

Two new refusals, both without data:

| Code | Token | Meaning |
|---|---|---|
| `-32018` | `unsupported_transfer` | The sender, target or route lacks transfer support. |
| `-32019` | `transfer_failed` | The transfer ID, caller role or state cannot admit that operation. |

A sender that did not opt into transfers keeps the existing
`unsupported_open_field` refusal. Capacity refusal remains `busy`. These
ordinary refusals no longer produce an invalid error that disconnects a strict
caller. Received semantic refusals retain their explicit codes across the bridge
for create, status, finish and chunk. Cancellation before ID allocation remains
`internal` / `transfer_unavailable`; post-created descriptor association failures
and already-ended endpoint generations remain unavailable. An otherwise valid
endpoint that ended before allocation uses `internal` / `transfer_unavailable`,
not a missing-capability refusal. Neither path invents a transfer ID,
failed terminal, successful publication or replay authority.

If accepting an allocated transfer cannot confirm the source start, the local
and bridged replies remain `internal` / `transfer_unavailable`, while the
transfer terminal is `unknown` / `source_start_unconfirmed`. This is not a
`transfer_failed` admission refusal and does not authorize a second start or
replay. An already-recorded authoritative terminal keeps its existing result.

File access follows OS permissions. Mapping native product permission settings
onto transfers is outside this release. The Go SDK publishes without replacing
through a descriptor-relative link, with an atomic no-replace rename fallback
for named unsupported-link errors. The JavaScript SDK uses a link and retains
the race between checking the destination's parent and publishing by path. A
detected parent change fails the transfer.

## Silent federated hosts

Each host probes its hub with the existing hosts request every 5 seconds.
The hub probes only roster-negotiated host links, using existing roster requests. After 15 seconds without an answer to its own probes, it marks the
link unresponsive and releases waiting calls once with `forward_lost`, keeping
the link and its ownership. A valid probe answer clears the mark and admits new
calls. Nothing uncertain is replayed, and a late reply does not settle the
same public call twice.

Explicit `session_id` lookups return `forward_lost` on a marked destination;
they never become successful empty lists. An availability-aware broad or
host-only `list` keeps confirmed rows and can add
`{"host": …, "products": [], "availability": "not_responding"}` for a silent
host. Ordinary forwarding refuses new calls once 256 are queued or pending on
one link. The TCP constructors request a nominal 150-second no-progress budget
with keepalive; this is not an elapsed-time guarantee. A healthy long-running
call still has no total execution deadline. A stuck worker behind a responsive
host is outside this detection, and genuine transport failures can still close
a link.

A group send keeps the written remote and local legs. A failed known leg has
`no_receipt` for `group@host`; host-enumeration failure uses the original group
without inventing hosts. Do not resend those uncertain legs.

The hub limits incoming calls from one host to 256 until their responses are
consumed. Excess calls get a per-call refusal, without ending ordinary work.
If a session ends while that host has 256 calls in flight through the hub, an
`owner_end` refusal restarts its hub link; its non-persistent cross-host lanes
end, while persistent lanes keep running. Parent trace state is cleared. A
full shared reply inbox could previously remove an origin during an ordinary
first-release burst. This does not remove every overflow/lifetime-loss limit:
retained mark-released destination correlations can fill their existing cap,
and a later owner-end/host-end cleanup at that cap can still close the link
(F1). Legacy host-only lists of a silent host can still return successful empty
lists (F3). Writer and transport backpressure remain separate closing limits.

## Hub federation policy

**EXPERIMENTAL: do not enable `--policy` on a real hub yet.**

`sessionbus-hub --policy /absolute/path/policy.json` independently limits named
groups and the directions in which hosts may create lanes. See
[FEDERATION-POLICY.md](../../bus/docs/FEDERATION-POLICY.md) for the full rules.
Without the option, forwarding is unchanged. SIGHUP validates and replaces the
policy atomically without restarting links; a bad reload retains the previous
policy. Host keys and every lane-rule host name must occur in the loaded secret
map; unknown names fail startup before listen or reject a reload while keeping
the previous policy. Successful reload logs once. SIGHUP without `--policy`
is logged and ignored. The opted-in refusal is `-32017`, `federation_policy_denied`, without
data. An invisible explicit session ID remains `unknown_session`.

Recorded creator relations preserve access to a caller's own lanes after a
reload. Under a restricted host pair, a recorded lane cannot resume or trace a
lane outside its recorded counterparts, even through a permitted named group.
Fresh nested spawn and access to its own recorded counterparts remain. The
relation table is in memory and is lost on hub restart. Newly enabling groups
cannot reconstruct creator relations from previously untracked spawns. A parent
resume carrying only its canonical private group can restore ONE-WAY calls to
the lane; it does not restore reverse notices, trace, transfers or nested-lane
verified identity. A resume carrying named groups adds no grant.

Each source/destination pair has a 256-entry live-plus-in-flight allowance,
returning `busy` at capacity. Other source hosts have independent allowances.
Closed but not forgotten entries retain slots; no roster negotiation means no
roster pruning. Empty `{}` host entries still enable tracking and associated
roster observations. Lanes-only and unlisted pairs retain the existing claimed
session/private-group identity hole. Local traffic is unaffected.

The existing trace reply filter preserves recorded symmetric creator/lane
counterparts. Other recipients across a restricted pair need a named group
allowed for both hosts; returned named groups are clipped, keeping required
private identity and exact owner/lifetime. Named groups govern eligibility at
that filter, not a new trace submission. A lanes-allowed pair without shared
named groups can list authentic destination products with zero sessions. A
responding pair cut off from both groups and lanes still hides its products;
the pre-existing marked not-responding placeholder remains possible. Product
inventory is discovery, not launch authority.

The shipped systemd unit needs an explicit `--policy` drop-in, copying its actual
installed command after clearing `ExecStart`; no policy environment fallback
was added. The policy guide records the procedure and experimental limits.
The relation-table redesign remains OPEN before policy reliance; no redesign,
fleet enablement, duplicate-converter or code-table parity refactor is claimed.
The matrix tests skip without their environment; the live matrix evidence below
was a one-off isolated run, not default CI coverage.

## Error validation

An overlong or otherwise malformed explicit host selector in `lane.describe`
or a fresh `lane.spawn` gets `unknown_host` before forwarding. Outgoing local,
forwarded, raw, typed and trace-wrapped federation errors share schema
validation. An invalid error becomes the valid `internal` error, with data
`"internal"`. Logging names the original supported code once per code, plus one
shared unknown-code bucket retaining the first actual numeric value. It never
logs error-data payloads or validator causes that can contain them. This
preserves the caller instead of exposing an error a strict SDK must reject.
Intentional malformed-wire rejection and genuine send failures keep their
existing behavior.

## Compatibility and release outputs

Availability and policy use independent negotiated capabilities. Older callers
keep their old list shapes, and policy refusals downgrade to `unknown_session`
for callers or hops without policy support. Availability support alone does
not enable policy errors. Update the hub to enforce the new policy; an older
hub cannot enforce it.

Every file-transfer endpoint requires matching refusal-aware daemon and Go/JS
SDK/kit versions. Codex endpoints also require the matching peer-common and
codex-peer set. Earlier unreleased transfer-capable development
builds have strict decoders that reject the new transfer errors; transfer
support alone does not make those builds compatible. The new transfer refusal
codes are not separately negotiated; an older strict transfer-capable kit
rejects them and closes its connection. There is no mixed-version
compatibility promise for those development builds and no new `transfer/2`
capability. Compiled Go consumers need a dependency update and rebuild.

The coordinated core release publishes npm `@sessionbus/kit@0.5.14`, eight
host/hub archives for Linux/macOS on amd64/arm64 with `SOURCE.txt` and
`SHA256SUMS`, and the same-commit Go SDK tag `bus/sdk/go/v0.5.14`. Binary and npm
publication run separately. Publishing does not install or restart a host.

## Evidence and limits

The bounded file-transfer checks used Linux, core `cd8aa6a9`, peer-common
`8c692a46`, codex-peer `28f58ecd` and native Codex 0.167.0. An offer to a peer
without transfer support returned `unsupported_transfer`; the same caller
continued with another query and lane close. The retained communication log
shows no disconnect through 09:28:06.478Z in that caller incarnation. A lane
with a 1-second auto-close remained connected and streaming during an accepted
1 GiB transfer, sampled 49.7 seconds after its separately observed native task
completion; the file subsequently arrived with the matching hash.

Those observations use finite communication records and extracted native
history. The installed Codex binary's own hash was not recorded. An offer
notice arrived after the prior Run ended and started another Run; this is not
proof of notice steering during busy work. Tool-only records reported as
unavailable/no-final-answer were kept as such, separately from observed native
completion. These checks do not establish a blanket runtime or compatibility
guarantee. Cross-host transfer through a hub (U7) remains unrun and is scheduled
after release.

Federation acceptance used core `7f54c591`, a private hub, two isolated daemon
hosts and example lane workers in one private network namespace on Linux:

- A 45-second path drop released the in-flight call with `forward_lost`. In the
  corrected recovery check, directed availability queries to the faulted host
  still showed it unresponsive 13.03 seconds after rule removal and first
  showed it responding at 14.04 seconds. The same original lane was then
  interrupted and collected. This roughly 14-second recovery delay is a
  user-visible test observation, not an SLA; the actual mark transitions and
  TCP cause were not recorded.
- During a 210-second path drop, the old socket and remote Worker were observed
  ended at 157.73 seconds. With one daemon stopped by SIGSTOP, an aggregate
  list returned partial rows plus `not_responding` after 17.55 seconds, before
  the fixed 35-second SIGCONT deadline.
- Malformed overlong hosts in describe and fresh spawn, and a valid absent
  host in describe, returned `unknown_host` while the same caller remained
  usable. No-policy messages passed in both directions.
- Policy acceptance passed in both directions: allowed delivery, hidden host
  omission and explicit-ID refusal, forbidden-group refusal, lane ACLs after
  reload, continuing existing work, revoked nonparent access and retained
  creator interrupt/collection of the original Run before acknowledgment.

The initial fixed-settle recovery attempt and the later incorrect hidden-ID
test oracle remain recorded as non-passing attempts; corrected acceptance does
not erase them. These were isolated Linux checks, with finite process/file
guards and ordinary cleanup, not changes to the real installed daemon. They
do not cover every policy branch, every platform or every product. Separate
Pi/OMP final-head checks are not claimed here. These live observations belong
to their named cd8/7f54 builds, not the later combined core-fix head. The final
core fixes have separate source/unit/race/SDK/JS/build evidence and passed
exact-head review and hosted CI before merging. Version and release publication
follow their own reviewed gates. No macOS live acceptance is claimed.

See the [v0.5.12 downgrade note](v0.5.12.md#downgrade) before returning to
older releases that reject duplicate lane names.
